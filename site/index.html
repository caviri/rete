How it works

Build once, host it, query from anywhere

1

Build

Turn Turtle, N-Triples, N-Quads, TriG, RDF/XML, JSON-LD or Jelly into one .rete file. It holds the triples, the indexes that find them and a Dataset Card that says what is inside.

The parts are laid out so a reader can find its way from the front of the file alone. The figure is a real file from the demo, drawn to scale.

rete build data.ttl -o data.rete --card
2

Host

Upload the file anywhere that serves byte ranges: object storage, GitHub Pages, Zenodo, your own web server. There is no database to run or keep up.

The engine runs where you query, in the browser tab, the notebook or the command line. The host only hands out the bytes it is asked for.

curl -r 0-1023 https://…/data.rete   # 206 Partial Content
3

Query

A client opens the file with one read of its front, then fetches only the dictionary chunks and index tiles the query touches. Pick a graph and a question: the marks are the ranges this page really fetched for it, set against a plain download on the same link.

Selective questions stay small. A question that scans the whole graph still has to read the whole graph.

rete sparql-url https://…/data.rete "SELECT …"
∞

Any size

The first read is the same whether the file is a few megabytes or a hundred gigabytes, and a lookup grows with what it finds, not with the file.

The biggest file in the catalog, the OpenCitations Index, holds 15.8 billion statements in 111 GB. Asking who cites one paper reads about 17 MB of it.

Cost

What it costs to publish a graph

A .rete file is storage. You pay to keep it and, on some hosts, for each byte a reader fetches. A SPARQL server is a machine that runs all month, whether anyone asks it anything.

When a server is the better choice

  • Questions that read most of the graph, often. Counting everything or scanning every statement is cheap for a server with the index on its own disk. A reader of a file has to fetch what it touches.
  • Data that changes all the time. A .rete file is not edited in place. You build it again and upload it.
  • Private data. A file in a public bucket is public. A host with signed links or access rules can limit who reads it.
How these numbers are worked out

A reader opens the file and asks one of the demo's questions. Bytes and requests are what this page's reader fetched from R2 on 2026-11-14, averaged over each graph's questions. A GB here is 230 bytes.

Prices, checked 2026-11-14:

  • Cloudflare R2: $0.015 per GB a month after 10 GB free, reads $0.36 per million after 10 million free, no charge for data out. The free allowance is per account; here nothing else is assumed to use it.
  • Amazon S3 Standard, us-east-1: $0.023 per GB a month, $0.0004 per 1,000 GET requests, data out $0.09 per GB after the first 100 GB a month, less past 10 TB.
  • Hugging Face buckets, checked 2026-11-18: public storage is free on a best-effort basis. Past "the first few gigabytes" Hugging Face asks you to upgrade to PRO, $9 a month, which includes up to 10 TB of public storage (storage limits). It names no number, so files up to 5 GB are priced on a free account. Data out is included up to 8 times what you store; it does not say over what period, or what happens past that. A bucket's download link redirects to Hugging Face's CDN and this page's reader follows it: the hermetic books' questions read the same bytes as from R2 and took 1.5 to 2.4 times as long.
  • GitHub Pages: free for a public repository, a 1 GB site and a soft limit of 100 GB of traffic a month. Git refuses files over 100 MiB.
  • Zenodo: free, up to 50 GB per record.
  • AWS Graviton machines, on demand, us-east-1, 730 hours a month: $0.0042 an hour for 0.5 GiB of memory up to $0.1071 for 16 GiB, each with 2 vCPUs. Disk (gp3) is $0.08 per GB a month. Data out is charged as for S3.

The servers are QLever (commit 18c097c, 2026-11-14) and Oxigraph 0.5.13. On 2026-11-15 we loaded each graph into both, from the same statements, and asked them the demo's questions. Each ran in Docker with 2 CPUs and 4 GB of memory, and each question returned as many rows as it does from the file. A server's price comes from what it used:

  • the smallest machine whose memory holds the server's peak while answering, its index and 512 MiB for the system, because the answers were timed with the index in memory;
  • a disk of 8 GB plus the index the server built, in whole GB;
  • each reader's answer sent out once.

At a million readers a month a server gets a question about every 2.6 seconds. The slowest answer we measured took 0.95 s, so one machine keeps up. We did not measure busier traffic, so the page stops there.

The OpenCitations Index has no server price: 15.8 billion statements is far past what fits in those runs, and we show only what we measured. The scripts and every number are in experiments/server-bench.

Not counted: the time it takes someone to run a server, backups, and building its index.

Use it

The same file, from wherever you work

Every client below asks the jazz graph from the demo the same question.

# the CLI ships as a Docker image; see Install for the alias
rete sparql-url https://data.graphplaza.com/linked-jazz/linked-jazz-2026-06-13.rete \
  "PREFIX foaf: <http://xmlns.com/foaf/0.1/>
   SELECT ?name WHERE { ?p foaf:name ?name } LIMIT 5"
# pip install rete-graph
import rete_graph as rete

g = rete.open("https://data.graphplaza.com/linked-jazz/linked-jazz-2026-06-13.rete")
rows = g.query("""PREFIX foaf: <http://xmlns.com/foaf/0.1/>
    SELECT ?name WHERE { ?p foaf:name ?name } LIMIT 5""")
for row in rows:
    print(row["name"].value)
// npm install rete-graph   (Node, or a worker in the browser)
import { open } from "rete-graph";

const g = await open("https://data.graphplaza.com/linked-jazz/linked-jazz-2026-06-13.rete");
const rows = g.query(`PREFIX foaf: <http://xmlns.com/foaf/0.1/>
  SELECT ?name WHERE { ?p foaf:name ?name } LIMIT 5`);
for (const row of rows) console.log(row.name.value);
# remotes::install_github("caviri/rete", subdir = "clients/r")
library(rete)

g <- rete_open("https://data.graphplaza.com/linked-jazz/linked-jazz-2026-06-13.rete")
rete_query(g, "PREFIX foaf: <http://xmlns.com/foaf/0.1/>
  SELECT ?name WHERE { ?p foaf:name ?name } LIMIT 5")
# install rete.mcpb in Claude Desktop, then ask in plain words:
Open https://data.graphplaza.com/linked-jazz/linked-jazz-2026-06-13.rete
and tell me who Mary Lou Williams played with.

Support

Help keep rete free and open

rete is a project by h4ck1ng.science. The engine, the file format and every client are open source under the Apache 2.0 license, and the public graphs on this page are free for anyone to query. Support keeps it that way.

Where support goes

🗄️ Hosting the graphs The catalog at data.graphplaza.com serves dozens of graphs, some over 100 GB, to anyone who asks for a byte range.
⚙️ Building new graphs Turning a large open dataset into a .rete file can take days of compute and a lot of memory.
⏳ Time Work on the engine, the file format, the clients and these docs.
