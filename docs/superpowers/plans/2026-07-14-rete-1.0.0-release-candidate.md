# Rete 1.0.0 Release Candidate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `v1.0.0-rc.1` with a stable `.rete` file-format baseline, stable Rust/CLI/WASM contracts, publishable crates, reproducible container builds, release-grade tests, current documentation, and a production-tested playground.

**Architecture:** Treat Rete 1.0 as a coordinated product release, not a crate-version edit. Format generation `0x05` is the first stable generation; pre-1.0 files remain unsupported and must be rebuilt, while every future stable reader must continue to read `0x05`. The release is produced from one commit through a checked-in Compose/devcontainer toolchain, then promoted through security, compatibility, API, coverage, browser, packaging, and live-R2 gates.

**Tech Stack:** Rust 1.92.0, MSRV Rust 1.87.0, Cargo, `wasm-bindgen`/`wasm-pack`, Binaryen Asyncify, Python 3 + `uv`, Docker Compose, Playwright, GitHub Actions, crates.io, GitHub Releases, GitHub Pages, Cloudflare R2.

## Global Constraints

- Work only on branch `release-1.0.0-rc1` in its isolated worktree.
- Do not add a `Co-Authored-By` trailer to any commit.
- Build, test, generate docs, and build WASM through `compose.yaml` or the `.devcontainer` configuration; do not depend on host Rust, Python, Node, zstd, or Binaryen. Native macOS/Windows release jobs are the sole exception because Docker cannot produce native Apple/MSVC artifacts; they use the committed `rust-toolchain.toml` and run the same artifact smoke test.
- `v1.0.0-rc.1` writes `.rete` format byte `0x05`; readers reject `0x01` through `0x04` with a rebuild instruction.
- Pre-1.0 files have no compatibility guarantee. No compatibility shim for format `0x04` is required.
- Every stable Rete release after 1.0.0 must read format `0x05`; a future incompatible writer format needs a new format generation and migration/rebuild documentation.
- `rete-core`, `rete-cli`, and `rete-wasm` are SemVer-governed, documented, publishable crates.
- Bootstrap `1.0.0-rc.1` manually from the devcontainer with an ephemeral crates.io token; do not run `cargo login` or store that token in GitHub. Publish later RCs and `1.0.0` through crates.io Trusted Publishing and GitHub Actions OIDC.
- The stable browser contract includes the default single-threaded build and the Asyncify remote-reader build. The `threads` feature remains experimental and is excluded from the 1.0 compatibility promise.
- Preserve bounds checks on all untrusted file and HTTP inputs. Every `unsafe` block needs a local `SAFETY:` argument and a test of its preconditions.
- Generated `docs/*.html`, `docs/playground.html`, WASM glue, and release artifacts must come from the same Git revision.
- A release candidate cannot ship with a RustSec vulnerability, a failing rustdoc link, an unpublishable crate, a stale generated page, or a red local/deployed playground gate.

## Audited Baseline

The 2026-07-14 audit established this starting point:

- Green: format, Clippy, workspace tests, `rete-core --no-default-features`, `rete-core --all-features`, benchmark build, CLI smoke, qbench ceilings, MSRV 1.86 check, web/no-modules WASM builds, 20/20 playground gate, deployed remote query, and 29/29 generated docs pages.
- Coverage: `rete-core` 86.27% lines; `rete-cli` 54.12% lines; browser/WASM line coverage is not measured.
- Security: `quick-xml 0.37.5` has RUSTSEC-2026-0194 and RUSTSEC-2026-0195; `crossbeam-epoch 0.9.18` has RUSTSEC-2026-0204; `anyhow 1.0.102` emits the RUSTSEC-2026-0190 unsoundness warning.
- Packaging: `rete-cli` and `rete-wasm` fail `cargo package` because their `rete-core` path dependency has no registry version; package metadata and license discovery are incomplete.
- Rustdoc: `RUSTDOCFLAGS=-Dwarnings cargo doc` fails on seven broken or private intra-doc links.
- Delivery: only `x86_64-unknown-linux-gnu` is released; the default Asyncify playground artifact is not rebuilt by CI; there is no checked-in Compose file.
- Docs/data: two broken internal links, stale Hugging Face hosting language, a clipped pyramid SVG label, a retired HF-based explorer, a tracked `__pycache__`, and approximately 150 MB of legacy `.rete` files in Git.

```rust
pub const CURRENT_FORMAT_VERSION: u8 = 0x05;
pub const MIN_STABLE_READ_VERSION: u8 = 0x05;

#[derive(Debug, thiserror::Error)]
pub enum HeaderError {
    #[error("buffer too small: need {HEADER_LEN} bytes, got {0}")]
    TooSmall(usize),
    #[error("bad magic: expected RETE")]
    BadMagic,
    #[error(

}
```

- [ ] **Step 2: Implement shared preflight and registry helpers**

The script starts with:

```sh
#!/bin/sh
set -eu

MODE=${1:?expected --bootstrap, --trusted, or --verify-auth}
VERSION=${2:?expected release version}
case "$MODE" in
  --bootstrap|--trusted|--verify-auth) ;;
  *) echo "unsupported publish mode: $MODE" >&2; exit 2 ;;
esac

test "$(git status --porcelain)" = "" || {
  echo "release worktree is dirty" >&2
  exit 1
}

  echo "HEAD is not tagged v$VERSION" >&2
  exit 1
}

    echo "CARGO_REGISTRY_TOKEN is required" >&2
    exit 1
  }
fi
```

Read the three package versions using `cargo metadata --no-deps --format-version 1`; require exact equality with `VERSION`. Inspect normalized manifests from `cargo package` and require dependent `rete-core` versions to be `=$VERSION`.

Implement `registry_checksum NAME VERSION` against `https://crates.io/api/v1/crates/${NAME}/${VERSION}` and `wait_for_registry NAME VERSION` with 5-second polling and a 120-attempt limit. HTTP 404 means absent; other non-2xx responses are hard failures.

- [ ] **Step 3: Implement ordered publication and checksum-safe resume**

For each package, run `cargo package --locked`, record `sha256sum target/package/${name}-${VERSION}.crate`, and query the registry:

```sh

else
  cargo publish --dry-run --locked -p "$name"

fi
```
