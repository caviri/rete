# Repository Guidelines

## Scope

These instructions apply to the whole repository.

## Project Shape

`rete` is a Rust workspace for a single-file, range-queryable RDF graph format.
The CLI builds immutable `.rete` files, the core crate owns the file format and
query engine, the WASM crate exposes browser bindings, and `docgen` renders the
static documentation site.

- `crates/rete-core`: file layout, dictionary/index/pyramid encoding, SPARQL,
  SHACL validation, reasoning, range readers, and robustness tests.
- `crates/rete-cli`: the `rete` binary and command handlers.
- `crates/rete-wasm`: `wasm-bindgen` browser API; default build is
  single-threaded and `file://` friendly.
- `crates/docgen`: Markdown-to-HTML docs renderer and shared docs-site design.
- `crates/bench`: dev-only Oxigraph comparison and reachability benchmark.
- `docs/*.md`: source documentation. `docs/*.html` is generated by `docgen`.
- `web/`: playground sources and WASM assets used to build `docs/playground.html`.
- `scripts/`: dataset converters (source → N-Triples), build/upload helpers, and
  `build_playground.py`. Per-source converters (`*_to_nt.py`, `*_to_nt.sh`) are the
  tracked recipe; the built `.rete` and raw `data/` are gitignored (they live in the
  bucket, not the repo).
- `skills/`: reusable agent skills that codify the graph-source → `.rete` → playground
  workflow — **rete-from-graph** (ingest + `rete build` + verify) and **rete-publish**
  (companions + bucket upload + catalog registration), each with reference docs and
  working utilities. Use/extend these instead of re-deriving the pipeline.

## Build And Test

The project is intentionally developed inside the Docker/devcontainer toolchain.
Do not assume the host machine has a compatible Rust, wasm, zstd, or Python
setup. Build the repo dev image with `docker build -t rete-dev -f
.devcontainer/Dockerfile .`, or open the folder in the devcontainer. The base
`rust:1.92-bookworm` image is not enough on its own because the repo also needs
the wasm target, `wasm-pack`, rustfmt, clippy, Python, and `uv`.

Useful checks from the repository root:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --exclude rete-bench --all-targets -- -D warnings
cargo test --workspace --exclude rete-bench
cargo test -p rete-core --no-default-features
cargo build -p rete-core --all-features
cargo build -p rete-bench
bash scripts/smoke.sh
```

For browser bindings:

```sh
wasm-pack build crates/rete-wasm --target web --out-dir ../../web/pkg
wasm-pack build crates/rete-wasm --target no-modules --out-dir ../../web/pkg-nomodules
uv run python scripts/build_playground.py
```

## Documentation

- Edit Markdown in `docs/*.md`; then run `cargo run -q -p docgen` and commit the
  regenerated `docs/*.html`.
- Edit shared docs-site layout and CSS in `crates/docgen/src/main.rs`, not in
  each generated HTML page.
- `docs/playground.html` is generated separately with
  `uv run python scripts/build_playground.py` from `web/playground.template.html`,
  `web/playground-src/*`, the no-modules WASM package, and staged datasets.
- Keep documentation critical and current. If source code and docs disagree,
  trust the code and tests first, then update the prose.
- Prefer precise claims over marketing language. Preserve caveats around v0 file
  stability, eager-vs-lazy SPARQL evaluation, federation limits, and browser
  threading limits.

## Playground Datasets And Hosting

The playground (`docs/playground.html`) loads a dataset one of two ways, both
registered in `web/playground-src/catalog.js`:

- **Embedded** — small graphs base64-inlined into the page at build time (instant,
  offline).
- **Remote-lazy** — bigger graphs range-queried over HTTP straight from the Hugging
  Face **bucket**, served through the `katospiegel-rete.hf.space` Space (a FastAPI
  Range+CORS file server). Only the bytes each query touches are fetched.

Catalog entries carry `datasets` / `datasetMeta` / `datasetExtra` / `examples`, plus
optional `shards: [urls]` (one logical graph split across independent `.rete` files,
**auto-federated** — every query UNION-fans across the shards) and `pmtiles` (a
tippecanoe vector-tile basemap for the "Tiles" output; can also be embedded inside the
`.rete` as a section). See `docs/browser.md` and `docs/federation.md`.

Build + publish (details in `skills/`): `rete build <in.nt> -o <out.rete>
--pyramid-algo types --card`, then `hf buckets cp <file> hf://buckets/.../playground/`.
In the Docker image the binary is `/work/target/release/rete` (not on `PATH`).

**Hosting caveat (do not "fix" by switching to resolve URLs):** the host MUST serve
range requests **directly**. HF dataset `resolve` URLs 302-redirect to a per-range
signed CDN URL, and rete's default reader uses **synchronous XHR**, which does not
follow a cross-origin redirect — so `resolve` URLs work from curl/CLI but fail in the
browser (and are ~2× slower). The Space (cpu-basic) serves directly but can wedge under
heavy concurrent load; recover with `HfApi().restart_space("katospiegel/rete")`
(~20 s). Diagnose Space-vs-code by hitting a bucket URL with `curl` (500/000/slow = the
Space, not rete).

## Commits

In this repo, commit **without** the Claude `Co-Authored-By` trailer.

## Code Conventions

- Rust 2021. Keep public APIs small and explicit.
- This code reads untrusted binary files from URLs. Bounds checks and clean
  errors are part of the product; do not replace them with unchecked indexing.
- Avoid `unsafe` unless there is a measured need and a narrowly documented
  safety argument.
- Keep the WASM default path free of native-only dependencies. Rayon belongs
  behind the `parallel` or `threads` feature gates.
- When adding CLI behavior, update `docs/cli.md`, `scripts/smoke.sh`, and focused
  tests in the relevant crate.
- When changing file format bytes, update `docs/SPEC.md`, header/layout tests,
  and compatibility notes.

## Generated And Large Files

- Do not commit new `target/` artifacts.
- Avoid committing local caches such as `__pycache__` unless the repository has
  deliberately started tracking them.
- Generated docs HTML is tracked and must stay in sync with Markdown.
